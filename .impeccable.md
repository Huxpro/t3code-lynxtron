## Design Context

### Users

T3 Code is for developers who drive coding agents throughout the day, often across several projects, threads, providers, devices, and local or remote environments. The interface must make navigation, model choice, context, and agent state legible without competing with the conversation or slowing down repeated actions.

### Brand Personality

Ambitious, restrained, and obvious. T3 Code should feel fast, dependable, and deliberately engineered rather than ornamental. It can have a recognizable identity, but never at the cost of information density, responsiveness, or trust in the current state.

### Aesthetic Direction

Use the existing T3 Code Web/Electron product as the visual and interaction source of truth. Preserve its compact developer-tool character, hierarchy, branded workspace chrome, and both light and dark themes. Lynxtron is a platform port, not an opportunity to invent a parallel visual language. Avoid generic AI dashboard styling, oversized card treatments, gratuitous glow/gradient effects, and platform adaptations that merely scale or truncate the Web layout.

### Design Principles

1. Share product anatomy and behavior; isolate only platform primitives and proven runtime gaps.
2. Make state truthful and immediate: connection, selection, navigation, focus, and destructive actions must never lie or flicker back silently.
3. Preserve dense hierarchy with intentional spacing; adapt components at bounded container breakpoints instead of shrinking the entire interface.
4. Treat the Composer and transcript as the primary work surface; supporting controls stay legible and secondary.
5. Match the Web/Electron baseline through tokens and shared compositions, then validate real interaction separately from visual capture.
6. Protect performance: no continuous repainting, avoid duplicate state projection, and keep platform adapters small and measurable.
