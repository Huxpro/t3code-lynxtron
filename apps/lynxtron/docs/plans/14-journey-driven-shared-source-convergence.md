## Baseline decision

Final5 is a trustworthy core-surface baseline, not product completion. Six states
have retained Web, Lynx-for-Web, and Native evidence: New Thread, Existing Thread,
Composer Hero, Model Picker, Quick Switch, and Review Diff. The fixed fidelity
model reports 16.82% conservative loss, but only 3.14% observed product residual;
14.13% is evidence debt. Therefore the next program must prioritize complete
causal journeys and missing product behavior over undirected pixel polishing.

The source-reuse boundary also needs a stricter interpretation. Shared projections
and composition boundaries exist, but the current product-surface module reuse is
still approximately 6.7% for the shell, 5.9% for Composer, and 2.9% for Model
Picker. A source-reuse item is not complete merely because a shared boundary exists.
Physical convergence remains active until duplicated product decisions are removed
or classified as platform leaves or hard islands.

## Program metrics

Track these independently. Never use one metric to imply another.

1. **Journey completion**: entry, pending, completion, failure, retry/reverse, and
   canonical receipt for each required action.
2. **Observed product residual**: measured current behavior only.
3. **Evidence debt**: unknown or stale cells; reduce it with the smallest current
   proof rather than new product code.
4. **Physical source reuse**: modules and lines built from the same production source.
5. **Duplicate product-decision LOC**: renderer-specific labels, ordering, validation,
   capability decisions, and action inventory that should be shared.
6. **Platform-leaf LOC**: input, native list, menu, measurement, bridge, and runtime
   adapters that are intentionally renderer-specific.
7. **Runtime quality**: startup, ready-to-interact, long-update latency, retained
   memory, connector payload frequency, bundle size, and renderer errors.

The existing 70% eligible module and line reuse target remains the ordinary UI
phase-exit target. M1 records the current duplicate-decision and platform-leaf
baseline for the surfaces it changes. M4 completes the cross-surface metric and
deletion audit. Neither phase may weaken the existing denominator or expand
exclusions.

## Universal execution protocol

Every phase goal must follow this sequence:

1. Read `AGENTS.md`, this master plan, the active phase file, Plan 12, the current
   compatibility matrix, gap atlas, fidelity report, and reuse report.
2. Record HEAD, upstream, worktree status, active plan status, and exact evidence
   baseline before editing.
3. Audit the phase prompt against current artifacts. Mark each requirement
   `complete`, `partial`, `blocked`, or `not-started`; do not redo complete work.
4. Select the smallest user-visible causal slice that advances the phase exit.
5. Move product decisions into shared source before adding renderer-local behavior.
6. Verify with focused tests, affected typechecks, ReactLynx scanner where relevant,
   affected builds, and one fresh semantic-ready 1280 x 820 run.
7. Use Browser-first Web/Lynx comparison for iteration and one exact-owned Native
   correlation for the phase-relevant interaction.
8. Update authored evidence sources, ledgers, plan status, and removal conditions.
9. Commit one concern and push it. A commit is a checkpoint, not a stopping condition.
10. Re-audit the phase. Continue the next safe unfinished slice until the phase exit
    is met, the user pauses, or the same external blocker has been reproduced enough
    to satisfy the blocked rule.

## Evidence policy

- Use one canonical snapshot within a causal journey. State-specific snapshots may
  diagnose a slice but cannot certify the final journey.
- Web/Electron remains the visual and behavioral authority.
- Browser evidence does not certify Native keyboard, focus, wheel, drag, selection,
  native menus, or OS dialogs.
- Computer Use must target the exact owned PID/window with fresh state before every
  action. DevTool owns geometry, runtime state, console, and exact LynxView captures.
- Keep the repository at or below 100 retained screenshots. Prefer structured JSON,
  assertions, hashes, and temporary screenshots when the budget is full.
- A successful build, listening server, attached DevTool session, or visible window
  is not semantic readiness. Require main transport, advancing sequence, canonical
  state, and zero unexpected renderer errors.
- Never use live `~/.t3/userdata`; copy or generate disposable state.
